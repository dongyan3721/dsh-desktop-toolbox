## 2. 先补便笺，保留统一权限模型

`sticky_note` 加入原生静态支持名单、catalog、UI 文案和 Agent 注册工厂。旧 v4/v5 配置未保存便笺授权时仍为 false；既有四项授权与快捷键不改。曾在“不支持”时期手工留下 `sticky_note:true` 的配置不能自动变成有效授权，须经一次明确用户授权；制定兼容迁移/授权版本标记并测试此情形，不以新增白名单直接激活历史字段。

首版便笺动作：

| 方法 | 作用 | 必须满足 |
| --- | --- | --- |
| `agent.notes.search` | 搜索同一便笺库 | 默认20/最多20项，offset≤10000、查询≤200 Unicode scalar；返回ID、标题、摘要、版本和窗口状态，非批量全文 |
| `agent.notes.read` | 按ID读取标题/Markdown/版本 | id≤80 scalar；有界正文，不能声称未保存的编辑已被读取 |
| `agent.notes.create` | 创建并持久化便笺 | 默认不弹窗；标题≤500 scalar、Markdown≤256KiB UTF-8；与人的列表和数据库一致 |
| `agent.notes.update` | 修改指定便笺 | `expected_updated_at` 为必填安全整数、至少指定 title/content_md；单事务CAS，版本单调前进，冲突不覆盖 |
| `agent.notes.open` | 显式显示已有便笺 | 同一个原生窗口/同一记录，重复打开前置，不新造第二份编辑状态 |

读取超过本轮上限时返回明确错误，不默默截断正文；不将旧 headless 的宽松/较大输入限制原封搬来。Node 与 Rust 采用同一边界和测试向量。实际模型工具可用单个 `toolbox_notes` 的固定 action enum 暴露五项。

**打开中的便笺是重点。** 旧 `save_closed_content` 虽有数据库 CAS，但没有统一约束现有 Vue 自动保存会话；直接写数据库可能被旧编辑器稍后覆盖。须复用/扩展非关闭式保存握手、每条便笺的写入序列及版本：先同步编辑草稿，再检查预期版本；更新成功使旧 autosave 失效，并把新内容/版本同步回同一窗口。用户期间又编辑则返回冲突/忙碌，保留草稿，不强制覆盖或关闭窗口。握手超时/取消不能谎称“已同步”。可先以关闭中的便笺实现首批单测，但公开完成验收必须包括打开窗口与自动保存竞争。

## 3. 必须在集成时处理的现有缺口

1. **服务和产品入口尚未接通。** Codex 扩展 toolboxDesktop 的 access/call/subscription，装配 Agent Entry、清理注册和轮询，按真实 installed SDK 接 attachment 服务。旧 notes/image headless 产品入口统一停用：便笺改走 GUI 的新授权接口，多媒体继续不支持。不能仅恢复旧便笺导出，否则会绕过开关并形成第二内核。
2. **原画布缺少命令确认。** 定稿 draw/snapshot 请求、窗口会话标识、坐标/DPI、ack、取消、超时与版本协议。Vue 在原 ScreenInkCanvas 执行并确认；快照来自该画布，不能用另一次裸桌面截图替代。只有完整接通后才广告两方法。共享范围文案按实际方法显示，避免未实现却写“可以绘制和快照”。
3. **真实图像传输缺失。** 接受受控 artifact_id，原生解析关联模块、授权代次、字节数与尺寸；分块传输满足4MiB帧限制，最终由真实 attachment backend 存储并作为 image block 返回。禁止以请求给定路径直接读盘。生成、分块读和交给模型均核对授权；撤回再授权也不能悄悄复活旧授权代次的产物。补过期清理、总量上限及卸载/重启语义。
4. **UI 有跨开关响应覆盖风险。** 当前 humanSeq/agentSeq 各自排序，但两个响应都会替换整份 catalog；旧“功能开关”响应仍可能覆盖较新的授权显示。跨模块也只有一个 pendingHuman/pendingAgent，允许并行时状态可能错配。须用统一刷新/版本机制或请求队列，加反序完成、旧 props 重载、失败回滚的可控测试；不仅检查模板字符串。
5. **支持目录不能长期维护三份不一致名单。** UI 当前另有四项硬编码，已与新增便笺冲突；改以原生 catalog 的明确 agent_supported 为显示依据，缺字段保守不授权。Node 仍只提供明确实现的五类工厂，并交叉核验 native methods；原生是最终边界。
6. **副作用发生后的取消结果需修正。** 当前 clipboard_write 在系统写入后仍可能返回 CANCELLED，dispatch 也在执行后统一检查取消。集成时区分“尚未执行的取消”“已提交结果”“执行结果未知/部分完成”；真实系统已变不能返回让调用者误以为完全未执行的结果，也不自动重试。补操作提交点后的取消/存储失败测试，便笺同样适用。
7. **两端输入/产物边界需一致。** 当前 Node 图像像素上限64M、原生16M；metadata/路径防护及撤回代次也尚未完整闭环。统一为契约值16M/16MiB，并测试 descriptor/实际字节/图像尺寸一致、链接越界、无效产物、不同模块授权隔离。原生校验不能依赖 Node 先过滤。

上述第4/6项是源码复核发现的执行路径风险，尚未通过集成故障注入复现；下一阶段先增加对应测试再修复，不把当前141项通过当作风险已排除。

## 5. 统一验收门槛

- 五模块各测功能/授权四组合、默认拒绝、重启保留、撤回与旧引用、伪造请求；五个人用专属模块没有工具或绕过接口。
- 便笺覆盖合法Unicode/Markdown、版本冲突、打开窗口脏草稿、自动保存迟到、同步超时、关闭/退出冲刷；失败不得丢草稿。
- 图像覆盖真实PNG、授权撤回与再授权、分块取消、错误大小/路径、受控存储与附件失效；模型能描述生成测试图中的可辨识标记，不能只返回路径。
- 人的原功能不依赖Agent授权；截图/注释/剪贴板等原键位、焦点、托盘、采集启停、保存/重启按H2继续实测。密码本认证仍由用户手工验收。
- Codex 在已登录 Electron 使用合成文本/图片/便笺/短时统计测试，不读取个人历史。各代理的fixture测试、合并自动测试和真实GUI/模型证据分别记录。
- 构建、临时文件和发布包全部在D盘本工作区，缓存复用D盘；不改原C盘工程，不自动导入个人数据。未达到M3前不替换当前可用预览。
